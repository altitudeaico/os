## Versioning rules

1. Historical versions are immutable. Do not overwrite `versions/v0.1.md`.
2. Any substantive change creates a new version file (for example `v0.2.md` or `v1.0.md`).
3. Update this register when a new version becomes the current baseline.
4. Use **major versions** (v1.0, v2.0) for formally adopted frameworks or material governance redesigns.
5. Use **minor versions** (v0.2, v1.1) for meaningful additions/clarifications that do not replace the core governance model.
6. Git commit history provides the audit trail, but the version files remain the human-readable historical record.
7. Family OS / Guardian implementation must not silently redefine the governance framework. If implementation exposes a policy decision not covered by the current framework, record the decision in a new framework version.
